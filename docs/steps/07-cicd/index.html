CI/CD, Fastlane & Publishing

GitHub Actions pipelines, Fastlane build automation, and publishing to TestFlight and Google Play

ci: GitHub Actions and Fastlane lanes

What you need before publishing

🍎

Apple Developer Account

$99/yr. Needed for TestFlight beta and App Store distribution. Sign up at developer.apple.com.

🤖

Google Play Account

$25 one-time. Needed for Play Store. Sign up at play.google.com/console. Takes 1–3 days for first approval.

🔐

Fastlane match

Syncs iOS certificates + profiles in a private git repo. One command sets up all team members and CI.

🗝

Android Keystore

A signing key generated once and stored forever. Never lose it — you cannot update an app without the original keystore.

⚙️

Fastlane + Bundler

Install: gem install bundler fastlane. Use Bundler to pin the Fastlane version for reproducible CI builds.

🏗

GitHub Actions

Free for public repos, 2000 min/month for private repos. macOS runners (required for iOS builds) cost 10× the Linux rate.

Publishing — step by step

🍎
iOS → TestFlight → App Store
Requires Apple Developer ($99/yr)
  1. Create an App ID in the Apple Developer portal. Match the bundle ID in ios/Playground.xcodeproj.
  2. Create the app record in App Store Connect (name, bundle ID, primary language).
  3. Run Fastlane match to set up certificates and provisioning profiles in a private git repo.
    bundle exec fastlane match init → choose git → enter private repo URL
  4. Generate AppStore certificates:
    bundle exec fastlane match appstore
  5. Build and upload to TestFlight:
    bundle exec fastlane ios beta
  6. In App Store Connect: add testers, fill metadata (description, screenshots, privacy URL), set age rating.
  7. Submit for review. First review typically takes 24–72 hours.
  8. After approval, release manually or enable automatic release on approval.
🤖
Android → Internal → Play Store
Requires Google Play ($25 one-time)
  1. Generate a keystore file once. Store it in a safe place — losing it means you can never update the app.
    keytool -genkey -v -keystore release.keystore -alias playground -keyalg RSA -keysize 2048 -validity 10000
  2. Add keystore config to android/gradle.properties (use env vars in CI — never commit passwords).
  3. Create the app in Google Play Console. Set the package name to match applicationId in android/app/build.gradle.
  4. Build a signed AAB (App Bundle — required for Play Store):
    bundle exec fastlane android build
  5. Upload to Internal Testing track first. Fastlane supply handles this automatically.
    bundle exec fastlane android deploy
  6. Set up the Play Console service account and download the JSON key for Fastlane supply auth.
  7. Fill store listing: description, screenshots (at least one per device type), feature graphic, content rating questionnaire.
  8. Promote from Internal → Closed Testing → Open Testing → Production (each can be staged rollout: 10% → 50% → 100%).

Fastlane configuration

Appfile

# fastlane/Appfile
app_identifier "com.yourname.playground"   # iOS bundle ID
apple_id        "you@example.com"
team_id         "XXXXXXXXXX"             # Apple Developer team ID

json_key_file   "fastlane/play-store-key.json"  # Android service account
package_name    "com.yourname.playground"        # Android applicationId

Fastfile — iOS lanes

# fastlane/Fastfile
platform :ios do

  lane :certs do
    match(type: "appstore")   # pull certs from private git repo
  end

  lane :staging do
    match(type: "appstore", readonly: true)
    increment_build_number(xcodeproj: "ios/Playground.xcodeproj")
    build_app(
      scheme:        "Playground",
      configuration: "Staging",
      export_method: "app-store"
    )
    # upload_to_testflight  ← uncomment when Apple Dev account ready
  end

  lane :beta do
    match(type: "appstore", readonly: true)
    increment_build_number(xcodeproj: "ios/Playground.xcodeproj")
    build_app(scheme: "Playground", export_method: "app-store")
    upload_to_testflight(skip_waiting_for_build_processing: true)
    upload_symbols_to_sentry(auth_token: ENV["SENTRY_AUTH_TOKEN"])
  end

end

Fastfile — Android lanes

platform :android do

  lane :build do
    gradle(
      task:           "bundle",
      build_type:     "Release",
      project_dir:    "android/",
      properties: {
        "android.injected.signing.store.file"     => ENV["KEYSTORE_PATH"],
        "android.injected.signing.store.password" => ENV["KEYSTORE_PASS"],
        "android.injected.signing.key.alias"      => ENV["KEY_ALIAS"],
        "android.injected.signing.key.password"   => ENV["KEY_PASS"],
      }
    )
  end

  lane :deploy do
    build
    supply(
      track:          "internal",  # internal → alpha → beta → production
      aab:            "android/app/build/outputs/bundle/release/app-release.aab",
      json_key:       "fastlane/play-store-key.json",
      skip_upload_apk: true
    )
  end

end

CI/CD Pipeline

Push / PR
→
ci.yml — Linux runner
yarn lint · yarn tsc --noEmit · yarn test --coverage · yarn audit · bundle size check
Merge → main
→
staging.yml — macOS runner (iOS) + Linux (Android)
fastlane ios staging → .ipa saved as artifact · fastlane android build → .aab saved as artifact
Git tag v*.*.*
→
release.yml — macOS + Linux runners
fastlane ios beta → TestFlight · fastlane android deploy → Play Internal · Sentry source maps · code-push OTA

GitHub Actions — release.yml skeleton

name: Release
on:
  push:
    tags: ['v*.*.*']

jobs:
  ios:
    runs-on: macos-14
    steps:
      - uses: actions/checkout@v4
      - uses: ruby/setup-ruby@v1
        with: { bundler-cache: true }
      - uses: actions/setup-node@v4
        with: { node-version: '20', cache: 'yarn' }
      - run: yarn install --frozen-lockfile
      - run: bundle exec pod install --project-directory=ios
      - run: bundle exec fastlane ios beta
        env:
          MATCH_PASSWORD:      ${{ secrets.MATCH_PASSWORD }}
          MATCH_GIT_BASIC_AUTH:${{ secrets.MATCH_GIT_TOKEN }}
          APP_STORE_CONNECT_API_KEY_KEY: ${{ secrets.ASC_API_KEY }}
          SENTRY_AUTH_TOKEN:   ${{ secrets.SENTRY_AUTH_TOKEN }}

  android:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: ruby/setup-ruby@v1
        with: { bundler-cache: true }
      - uses: actions/setup-node@v4
        with: { node-version: '20', cache: 'yarn' }
      - run: yarn install --frozen-lockfile
      - run: bundle exec fastlane android deploy
        env:
          KEYSTORE_PATH: ${{ secrets.KEYSTORE_PATH }}
          KEYSTORE_PASS: ${{ secrets.KEYSTORE_PASS }}
          KEY_ALIAS:    ${{ secrets.KEY_ALIAS }}
          KEY_PASS:     ${{ secrets.KEY_PASS }}

Store submission checklist

🍎
App Store Connect
  • ☐ App name (max 30 chars)
  • ☐ Subtitle (max 30 chars)
  • ☐ Description (max 4000 chars)
  • ☐ Keywords (max 100 chars, comma-separated)
  • ☐ Support URL
  • ☐ Privacy Policy URL (required)
  • ☐ Screenshots: iPhone 6.9" + iPad 13" (required)
  • ☐ App icon 1024×1024 PNG (no alpha)
  • ☐ Age rating questionnaire
  • ☐ Sign-in credentials for reviewer (if auth required)
  • ☐ Export compliance — does app use encryption?
🤖
Google Play Console
  • ☐ Short description (max 80 chars)
  • ☐ Full description (max 4000 chars)
  • ☐ App icon 512×512 PNG
  • ☐ Feature graphic 1024×500 PNG
  • ☐ Screenshots: Phone + 7" tablet (required)
  • ☐ Privacy Policy URL (required)
  • ☐ Content rating questionnaire
  • ☐ App category
  • ☐ Data safety form (what data is collected, shared)
  • ☐ Target audience age
  • ☐ Test track promoted to production with release notes

Critical warnings

Never lose your Android keystore. Google does not allow key resets. If you lose the keystore you must publish a new app with a new package name. Store it in a password manager or encrypted backup — not only in the CI environment.
iOS keychain on first install. iOS Keychain data survives app uninstall. A reinstall from a different user may auto-read the previous user's token. Call Keychain.resetGenericPassword() on first launch after fresh install (check an MMKV flag to detect this).
Never OTA-update native code. code-push / EAS Update only patches the JS bundle. If your update includes changes to native modules, run a full store release instead — an OTA native mismatch crashes on launch.
Build numbers must always increase. App Store and Play Store reject builds with a build number equal to or lower than a previously uploaded build. Fastlane's increment_build_number handles iOS. For Android, increment versionCode in build.gradle or use Fastlane's android_set_version_code.
macOS runners are expensive. GitHub-hosted macOS runners consume 10 minutes of quota per 1 minute of wall time. Only run the iOS build on tag pushes — not on every PR — to stay within the free tier or control costs.
Until you have store accounts, the staging.yml workflow saves the .ipa and .aab as GitHub Actions artifacts. Download them from the Actions tab and install manually via Xcode Devices (iOS) or adb install (Android).
